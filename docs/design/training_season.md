# Training Season: Aggregated Weaknesses and a Ranked Candidate Slate

Status: **accepted — milestone M8, in progress.** Deepens the existing
single-shot training loop into the "training factory" experience: run a full
season against the NPC population, see *where* the agent loses across the whole
roster, and choose from a ranked, validated slate of prompt-evolution options.

## Why

`opennego train` (`run_training_loop`) today patches from **one** opponent's
battle report: it sparring-tests the roster, selects a single result, generates
**one** candidate, reruns, and compares (with optional held-out validation).
That answers "fix the worst single match," not "what does this agent
systematically get wrong, and which fix helps most?"

A real training experience aggregates across the population and offers choices:

- A buyer might over-concede in *closing* against hardline anchors, *and* fail
  to inspect lemons, *and* overpay low-reputation sellers. One patch can't be
  judged without seeing the whole weakness distribution.
- Generating several targeted candidates and validating each on held-out NPCs
  turns evolution from a guess into a ranked, evidence-backed menu.

## Model

1. **Baseline season.** Run a sparring suite across the opposite-role roster,
   split into train / held-out sets (reusing `split_opponent_roster`). Safety
   (scam) profiles always appear in both sets, exactly as the current loop.

2. **Weakness aggregation.** Read every train-set battle report and aggregate
   its `weaknesses` and `lessons` by `(phase, category)`:
   - `frequency`: how many opponents surfaced it,
   - `severity_weight`: max/mean of `{low:1, medium:2, high:3, critical:4}`,
   - `mean_policy_score`: mean score of matches where it appeared (lower = it
     hurts more),
   - `opponents`: example archetypes that triggered it.
   Rank by a deterministic `priority = frequency * severity_weight * (1 -
   mean_policy_score)` (ties broken by phase order then category name). The
   result is a `opennego.weakness_profile.v1` artifact — useful on its own as a
   diagnostic, and the input to the slate.

3. **Candidate slate.** For each of the top-`k` weaknesses, synthesize a
   *focused* battle report (the selected report filtered to that weakness's
   lessons) and feed it to the existing `generate_strategy_candidate`, so the
   patch targets that weakness. Each candidate is then validated by rerunning
   the suite with it applied; we record the held-out mean-score delta and a
   generalization verdict (`generalizes` / `train_only`), reusing the M2
   overfit machinery. Candidates are ranked by held-out delta, with
   `train_only` (overfit) candidates demoted below any generalizing one.

4. **Recommendation + trajectory.** Recommend the top-ranked generalizing
   candidate (or "no improvement found" if none beats baseline out of sample),
   and report the baseline→best mean-score trajectory across the roster. The
   user still chooses; nothing is auto-applied.

## Artifacts

- `opennego.weakness_profile.v1` — the ranked aggregated weaknesses.
- `opennego.training_season.v1` — the full season: weakness profile, the ranked
  validated candidate slate, the recommendation, and the trajectory.

## CLI

`opennego train-season --role buyer --k 3 [--holdout-seed N]` emits the season
artifact as JSON and (optionally) a static HTML report, mirroring the existing
`spar` / `train` commands. Deterministic and no-key by default; the slate is
generated by the rule-based coach unless a BYOK coach is configured.

## Scope

In: aggregation, the validated ranked slate, the season runner, the CLI, and a
report. Reuses the existing sparring, coaching, evolution, and held-out
validation; adds no new agent classes and no schema changes to the battle
report.

Out: auto-applying a candidate (the user chooses), co-evolution against
non-fixed opponents (a separate track), web-client surfacing (follow-up),
protocol v2.
